# Stage 0 authentication runtime evidence

October 22, 2026. Task 1 local implementation and hosted research harness. Live authentication
remains disabled; no providers, application routes or remote migrations were added.
The password KDF is **pending**, not approved for credential storage. Enterprise
federation may change which password functionality Ovelle needs to own; see the
[SSO exploration](stage0-federated-login.md) before implementing Task 2 or Task 3.

## Runtime and test choices

- Preserve the deployed configuration's `2026-10-06` compatibility date; no Node
  compatibility flag is required for the candidate hashes or Stage 0 contracts.
- Pin Vitest `4.1.12`, the official `@cloudflare/vitest-plugin` `1.4.7`, Miniflare
  `5.20261019.2-beta`, workerd `1.20261019.1` (lockfile), esbuild `0.28.2` and Wrangler
  `4.152.0`. Wrangler was previously resolved to `4.148.0`; align the CLI, probe and
  official test integration on one runtime. Miniflare's prerelease status is
  explicit; it follows the current official plugin's dependency, not a hosted
  runtime version guarantee. The final install reports zero npm audit findings.
- Pin `@noble/hashes` `2.4.0` as a **development-only feasibility dependency**.
  Its [published audit scope](https://github.com/paulmillr/noble-hashes#security)
  excludes Argon2. This does not meet the proposed audited-implementation gate.
- `vitest.stage0.config.mts` uses the official Workers plugin, a local D1 binding,
  and no deployed Wrangler configuration or secrets. The `.mts` extension avoids
  loading an ESM-only plugin through the root package's CommonJS configuration.
- The test suite and benchmark both run on the repository floor, Node `22.12.0`,
  as well as the installed Node `26.7.0`. New code has its own TypeScript check,
  included in `npm run check`; the Workers test suite runs in the existing
  secret-free CI typecheck lane. No production binding is needed for CI.

## Reproduction and measurement boundary

```sh
npm ci
npm run test:stage0
npm run check:stage0
npm run benchmark:stage0-password
```

The benchmark bundles `scripts/stage0-password-probe.ts` and dispatches synthetic
requests into a local workerd isolate through Miniflare. It neither deploys the
probe nor accepts real passwords. No D1, R2, mail or identity-provider connection
is configured; outbound requests are blocked. Keep the research modules outside
the application Worker import graph.

Measure elapsed time in the Node caller using `performance.now()`. Worker timers
are not used for CPU accounting. Samples include local dispatch/serialization;
they are not hosted CPU, billing, memory-usage, load or latency guarantees. Each
candidate has one first-call measurement, then five samples each for derivation,
matching-password rederivation and wrong-password rederivation. The verification
comparison is a synthetic vector check, **not a production password verifier**.
Both outputs are compared with independent fixed vectors generated by Node
`26.7.0`'s OpenSSL-backed `pbkdf2Sync` and `argon2Sync`, with the exact fixture
password and 16-byte salt in the probe. The benchmark itself requires no Node
Argon2 implementation and works on Node 22. Never use those public fixture values
for real credentials. Account passwords will require random per-password salts
and a versioned bounded format in Task 3.

## Observed results

Local Ubuntu x64, AMD Ryzen 7 3700X; Node `26.7.0`. Raw samples, first-call timings,
versions and environment are in [the local record](stage0-runtime-local.json).
The [Node 22.12.0 record](stage0-runtime-node22-local.json) independently exercises
the supported floor. These measurements use the same compatibility date and
installed workerd build as the harness, not the deployed Cloudflare service.

| Candidate | Parameters | Derivation median | Match median | Mismatch median | Local result |
| --- | --- | ---: | ---: | ---: | --- |
| Native Web Crypto PBKDF2-HMAC-SHA256 | 600,000 iterations; 16-byte salt; 32-byte output | 68.610 ms | 68.779 ms | 67.830 ms | Correct independent vector; no work-factor fallback |
| Noble Argon2id | 19,456 KiB; 2 passes; parallelism 1; 16-byte salt; 32-byte output | 166.230 ms | 159.561 ms | 159.008 ms | Correct independent vector; audit gate unmet |

These profiles follow the current [OWASP password-storage guidance](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html).
Do not reduce the work factor to satisfy a runtime limit. This local Web Crypto
implementation accepts 600,000 iterations; that establishes nothing about the
hosted runtime's iteration limits. `validateCandidateParameters` refuses weaker,
unknown and unbounded research profiles. Neither candidate is wired to live auth.

## Configuration and contracts delivered

`loadStage0Config` separates local fixtures, development and production. Hosted
configuration requires exact environment-specific origins/RP IDs, an email sender
and Turnstile site/secret settings. Local bypass flags are rejected in hosted
configuration; a flag cannot enable live auth while the runtime decision is
pending. Existing public routes do not call this loader. Configuration validation
does not establish a provisioned sender, working Turnstile or real mail delivery.

Shared interfaces cover D1 request context, injected clock/IDs/mailer, principals,
commands and scoped grants. Unknown action/error values fail closed. Mail fixture
acceptance means provider acceptance only; no actual email is sent. Federation
assurance and connection contracts remain proposals in the SSO document and are
not represented as password/passkey authentication by the current principal type.

## Gates before password account implementation

1. Confirmed: direct OIDC for Google, Microsoft and tenant-specific Entra ID,
   without a broker or new paid authentication service. Local passwords remain
   optional and gated on runtime evidence.
2. Authorized: a separate development-only hosted probe:
   fixed synthetic inputs, no app routes, no database, no user credentials, bounded
   calls, restricted access, explicit CPU limit and cleanup. Collect actual hosted
   success/failure and CPU metrics for the exact version, then record memory and
   CPU headroom against the chosen plan/limit. Hosted CPU/headroom are currently
   recorded below; no candidate is approved for the free CPU budget.
3. Prefer testing native PBKDF2 next because the local candidate works and avoids
   the observed Argon2 audit gap. This is a test-order recommendation, not a frozen
   KDF decision. If hosted Web Crypto rejects 600,000 iterations or lacks headroom,
   record that failure; do not fall back to 100,000. Reconsider an audited compatible
   implementation, a dedicated hashing service or broker-owned credentials.
4. Review provider/sender, passkey assurance, recovery and federation policies,
   select an evidenced audited implementation and a bounded versioned hash format,
   and update the spec before Task 3. Local passing tests do not clear these gates.

Task 1's local implementation and hosted investigation are available. No tested
KDF clears the free-runtime gate, so password implementation remains blocked. Tasks 2–11 are not implemented by this change.

## Hosted probe procedure

The manual `Stage 0 hosted password runtime probe` workflow uses the existing
repository deployment token on a hosted GitHub runner, restricted to development.
It uploads randomly named run-owned temporary Workers, with no application/data
bindings, a random bearer secret, ten-minute expiry and only fixed synthetic
inputs. An authenticated health response confirms routing before the three KDF
requests per candidate. The API must report the configured 10 ms CPU limit before
measurement begins. No billing/plan/provider configuration changes are made.
Cleanup runs in `finally` and an independent always-run step, with deletion
readback. The one-day artifact records source SHA, responses and external HTTP
elapsed times, without tokens. Three mock tests cover delayed route propagation, successful procedure,
abort/cleanup when the free-budget CPU setting cannot be confirmed and continued
cleanup after a persistent first-resource failure. The runner also attempts
read-only GraphQL CPU telemetry; missing Analytics permission or delayed metrics
are recorded as unavailable, without changing token permissions.

Dispatch after publishing this workflow to development:

```sh
gh workflow run stage0-runtime-probe.yml --ref development
```

Cloudflare's [free Workers CPU allowance](https://developers.cloudflare.com/workers/platform/limits/)
is 10 ms per invocation. Setting that budget does not verify account billing
status or guarantee zero marginal costs on an existing paid account. A few
successful calls do not establish sustainable headroom; external HTTP elapsed
time must never be reported as CPU time. Keep passwords gated without an approved
implementation and actual CPU/headroom evidence.

## Initial hosted result — October 22

[Workflow 39863874464](https://github.com/Atripix-Design/ovelle/actions/runs/39863874464)
succeeded at source `3258bc6e4c80a5ea8a9228bf17e301b5d2104ebd`.
The [retained raw report](stage0-runtime-hosted.json) records all six KDF responses
and confirmed cleanup. Both Workers had a read-back CPU setting of 10 ms.

- Hosted Web Crypto **rejects** the 600,000-iteration PBKDF2 profile with
  `NotSupportedError`: iteration counts above 100000 are not supported. All three
  requests failed before derivation. HTTP 200 carries the probe's error object;
  it does not mean hashing succeeded. Local workerd acceptance did not transfer.
- Noble Argon2id returned two correct independent-vector matches and one correct
  mismatch at the full 19 MiB/two-pass profile. HTTP elapsed times were 821, 1908
  and 1020 ms, including network overhead. Those are **not CPU measurements**.
  Cloudflare documents [CPU rollover behavior](https://developers.cloudflare.com/workers/observability/metrics-and-analytics/),
  so a successful request with a configured 10 ms limit does not demonstrate
  sustainable free-tier operation. The implementation's audit-scope gap also
  remains. This is hosted correctness evidence, not password-storage approval.
- Both temporary Workers were deleted and checked absent; the always-run cleanup
  step also succeeded. No application/provider/database or billing changes.

**Decision:** reject hosted Web Crypto PBKDF2 for this profile; do not downgrade
iterations. Keep the password gate closed pending an acceptable implementation
and CPU headroom. Continue the selected direct OIDC design without a broker fee;
no claim is made that all future hosting or identity-provider services are free.

## Hosted CPU result and free-first decision

[Telemetry run 39864098017](https://github.com/Atripix-Design/ovelle/actions/runs/39864098017)

`AccountWorkersInvocationsAdaptiveQuantiles` describes `cpuTimeP50` and
`cpuTimeP99` in **microseconds**; divide by 1,000 for milliseconds.

| Probe | Requests represented | CPU P50 | CPU P99 | Decision |
| --- | ---: | ---: | ---: | --- |
| PBKDF2 600k | 4 | 0.424 ms | 0.831 ms | Iteration-cap rejection only; no hash ran |
| Argon2id 19 MiB / t2 / p1 | 4 | 350.472 ms | 1,257.565 ms | CPU exceeds free allowance; no free-runtime approval |

These are small, potentially sampled aggregate observations across the three KDF
attempts and authenticated health request, not per-operation benchmarks or a
production latency promise. Even with that limitation, the observed Argon2 CPU
cost is far above 10 ms. The runtime's rollover behavior explains why successful
HTTP responses cannot be treated as evidence of fitting the allowance. No weaker
parameters were tried; the audit-scope issue also remains unresolved.

**Free-first ruling:** direct OIDC remains the selected login direction, without a
broker subscription. Neither tested password profile is acceptable for the free
Workers runtime. Keep local-password routes disabled and credentials optional in
the account design. This does not prove every possible KDF/runtime combination is
impossible; any future password candidate needs separate correctness, audit and
CPU-headroom evidence. Do not claim that OIDC or passkey routes are implemented by
this runtime investigation. No plan upgrade or new paid service was configured.
